## 3. Phase 0: ระบบลงเวลาอัจฉริยะ (Smart Attendance Foundation)

### 3.1 ปรัชญาการออกแบบ (Core Philosophy)

#### 3.1.1 ยืดหยุ่นแต่ตรวจสอบได้ (Flexible yet Auditable)

ไม่ตัดสิทธิ์พนักงานทันทีหากอยู่นอกพื้นที่ แต่เน้นการเก็บหลักฐานและเหตุผลเพื่อให้ HR ตรวจสอบย้อนหลัง

#### 3.1.2 ลดความซับซ้อนของระบบ (Lean & Practical)

ใช้จิตวิทยาและกระบวนการออฟไลน์เข้ามาช่วยลดภาระการเขียนโปรแกรมที่ไม่จำเป็น

#### 3.1.3 ภาระงานของ HR ต้องต่ำที่สุด (Zero-Burden on HR)

ออกแบบให้รองรับพนักงานจำนวนมากได้ด้วยระบบสืบทอดสิทธิ์ (Inheritance) และการจัดการแบบกลุ่ม (Bulk Actions)

---

### 3.2 องค์ประกอบข้อมูลหลัก (Core Conceptual Entities)

#### 3.2.1 สถานที่ทำงาน (Location Master)

บันทึกจุดที่ตั้งต่างๆ ขององค์กร (สำนักงานใหญ่, สาขา, ไซต์งาน)

| ฟิลด์ | คำอธิบาย | ตัวอย่าง |
|---|---|---|
| `location_id` | รหัสสถานที่ | LOC-001 |
| `name` | ชื่อสถานที่ | สำนักงานใหญ่ |
| `latitude` | ละติจูด | 13.7563 |
| `longitude` | ลองจิจูด | 100.5018 |
| `radius_meters` | รัศมีปลอดภัย | 150 (ค่าแนะนำ: 100–150 ม.) |
| `address` | ที่อยู่ | 123 ถ.สุขุมวิท... |

**หมายเหตุ:** รัศมีมาตรฐานแนะนำที่ **100–150 เมตร** เพื่อรองรับความคลาดเคลื่อนของ GPS ในอาคาร

#### 3.2.2 แม่แบบนโยบายเวลา (Attendance Policy Templates)

ชุดกติกาเวลาทำงานที่สร้างไว้ล่วงหน้า เพื่อให้ HR นำไปผูกกับพนักงานได้ทันที

| แม่แบบ | เวลาเข้า | เวลาเลิก | ผ่อนผัน (Grace) |
|---|---|---|---|
| ออฟฟิศ | 08:30 | 17:30 | 15 นาที |
| กะโรงงาน | 08:00 | 17:00 | 0 นาที (เคร่งครัด) |
| ยืดหยุ่น/เซลส์ | 10:00 | 19:00 | 30 นาที |

#### 3.2.3 โปรไฟล์การทำงานของพนักงาน (Employee Work Profile)

ข้อมูลพนักงานแต่ละคนจะผูกอยู่กับ 2 มิติ:

- **มิติด้านสถานที่:** สังกัดสาขาใดเป็นหลัก หรือเปิดโหมด WFH + พิกัดบ้าน
- **มิติด้านกติกาเวลา:** ถือครองแม่แบบนโยบายเวลาชุดใด

**คุณสมบัติเพิ่มเติม:**
- รองรับการสลับค่าแบบกลุ่ม (Bulk Action) โดย HR
- มีสถานะ `wfh_mode` (เปิด/ปิด) และ `wfh_location_id`

#### 3.2.4 บันทึกธุรกรรมการลงเวลา (Attendance Logs)

| ฟิลด์ | คำอธิบาย |
|---|---|
| `log_id` | รหัสบันทึก |
| `employee_id` | รหัสพนักงาน |
| `timestamp` | เวลาที่กดจริง (จากเซิร์ฟเวอร์) |
| `log_type` | ประเภท: `check_in` / `check_out` |
| `latitude`, `longitude` | พิกัดจริงที่มือถือส่งมา |
| `accuracy_meters` | ความแม่นยำของ GPS |
| `distance_meters` | ระยะห่างจากจุดเป้าหมาย |
| `time_status` | `on_time` / `late` / `early_leave` |
| `location_status` | `inside` / `outside` / `auto_approved` |
| `flag_status` | `none` / `yellow` / `red` |
| `reason` | เหตุผลประกอบ (กรณีนอกพื้นที่) |
| `photo_url` | ที่อยู่ของภาพถ่ายยืนยัน |
| `device_info` | ข้อมูลอุปกรณ์ (สำหรับ mock location check) |

### 3.3 ตรรกะการประมวลผล (Evaluation Decision Engine)

ทุกครั้งที่พนักงานกดปุ่มลงเวลา ระบบจะประมวลผลตามลำดับขั้น:

```text
[พนักงานกดปุ่มลงเวลาบนมือถือ]
       ↓
[ขั้นที่ 1: ตรวจสอบความพร้อมของอุปกรณ์]
  → ตรวจสอบ GPS Accuracy (ถ้า > 100 ม. → แจ้งเตือนให้เปิด Wi-Fi)
  → ตรวจสอบ Mock Location Flag (ถ้าตรวจเจอ → บันทึกแต่ติด Flag แดงเข้ม)
  → เปิดกล้องสดเพื่อแนบภาพ (ถ้าถ่ายไม่ได้ → ลงเวลาต่อได้ แต่บันทึก FLAG: PHOTO_MISSING)
       ↓
[ขั้นที่ 2: ค้นหาเป้าหมาย]
  → ตรวจสอบว่าพนักงานอยู่ในโหมด WFH หรือโหมดเข้าสำนักงาน/ไซต์งาน
       ↓
[ขั้นที่ 3: ตรวจสอบพิกัด (Spatial Verification)]
  → คำนวณระยะห่างระหว่าง "พิกัดมือถือ" กับ "พิกัดเป้าหมาย"
  → กรณีอยู่ในรัศมี: ผ่านเงื่อนไขสถานที่ทันที
  → กรณีอยู่นอกรัศมี 100–200 ม. + มีเหตุผล: Auto-Approve (Flag เหลือง)
  → กรณีอยู่นอกรัศมี: บันทึกทันทีพร้อม FLAG: OUTSIDE_RADIUS → รอ HR ตรวจ
       ↓
[ขั้นที่ 4: ตรวจสอบเวลา (Temporal Verification)]
  → นำเวลาปัจจุบันไปเทียบกับ "แม่แบบนโยบายเวลา" ของพนักงานคนนั้น
  → ถ้าเวลา <= เวลาเข้างาน + เวลาผ่อนผัน → สถานะ "ตรงเวลา"
  → ถ้าเวลาเกิน → สถานะ "มาสาย" พร้อมคำนวณจำนวนนาทีที่สาย
       ↓
[ขั้นที่ 5: บันทึกภาพถ่ายยืนยัน]
  → เปิดกล้องสด → ถ่ายภาพบรรยากาศ ณ ตอนนั้น
  → อัปโหลดภาพ → เก็บ URL ใน Attendance Log
  → ไม่ใช้ AI เปรียบเทียบภาพ
       ↓
[ขั้นที่ 6: สรุปและตอบรับ]
  → บันทึกลงฐานข้อมูล
  → ส่งการ์ดยืนยันผล (Flex Message) เข้า LINE พนักงานทันที
```

> **กติกาที่ใช้จริง (อัปเดต 2026-09-30, งาน 026):** การลงเวลา **ไม่ถูกบล็อก** ไม่ว่ากรณีใด — ภาพถ่ายใช้ไม่ได้,
> ไม่มีสัญญาณ GPS, อยู่นอกพื้นที่ หรืออยู่นอกช่วงเวลาของรอบ ระบบจะบันทึกให้ครบพร้อม **flag** แล้วให้
> ฝ่ายบุคคลตรวจสอบ ยกเว้นกรณีที่เป็นการบันทึกซ้ำจริง ๆ เช่น ลงเวลารอบนี้ไปแล้ว หรือยังไม่ได้กำหนดแม่แบบ
> เวลาให้พนักงานคนนั้น (กรณีหลังผู้ใช้จะเห็นข้อความไทยให้ติดต่อฝ่ายบุคคล)
>
> **Flag ที่ระบบสร้างได้** (`backend/app/checkin_logic.py`; ป้ายไทยใน `attendance_labels.py`):
> `LATE` มาสาย · `OUT_OF_WINDOW` นอกช่วงเวลาของรอบ · `OUTSIDE_RADIUS` นอกพื้นที่ · `NO_GPS` ไม่ได้พิกัด ·
> `LOW_ACCURACY` พิกัดไม่แม่นยำ · `PHOTO_MISSING` ไม่มีรูป · `NO_LOCATION_ASSIGNED` ยังไม่ได้กำหนดสถานที่ทำงาน
>
> **สถานะการตรวจสอบของฝ่ายบุคคล:** `CLEAN` ปกติ (ไม่มี flag) · `PENDING_REVIEW` รอตรวจ ·
> `ACCEPTED` ยอมรับแล้ว · `REJECTED` ไม่ยอมรับ
>
> ภาพถ่าย: หน้า LIFF เปิดกล้องสดโดยตรง (ไม่เลือกจาก Gallery) แต่ถ้าถ่ายไม่ได้ ระบบยังลงเวลาให้เสมอ
