# คู่มือการติดตั้งและตั้งค่า LINE OA & LIFF Integration

เอกสารนี้อธิบายขั้นตอนการกำหนดค่าระบบเชื่อมต่อ LINE Official Account (OA) และ LINE Front-end Framework (LIFF) สำหรับระบบ **WorkDee** เพื่อให้ระบบสามารถรับข้อความจาก Webhook, ส่งการแจ้งเตือน Push Message, และให้พนักงานสามารถผูกบัญชี LINE ผ่าน LIFF App ได้อย่างสมบูรณ์

---

## 1. ภาพรวมสถาปัตยกรรม (Architecture Overview)

ระบบ WorkDee รองรับการตั้งค่า LINE Credentials แบบไดนามิกผ่าน **Admin Dashboard Settings** ซึ่งข้อมูลจะถูกบันทึกในฐานข้อมูล (`app_settings`) และมีระบบ Fallback ไปดึงจากไฟล์ `.env` หากไม่ได้กรอกข้อมูลในฐานข้อมูล

### ข้อมูลสำคัญที่ต้องใช้:
1. **LINE Channel Access Token**: ใช้สำหรับอนุญาตสิทธิ์ให้ระบบส่งข้อความหาผู้ใช้ (Push/Reply)
2. **LINE Channel Secret**: ใช้ตรวจสอบความถูกต้อง (Verify Signature) ของข้อมูลที่ส่งมาจาก LINE Webhook
3. **LINE LIFF ID**: ใช้สำหรับเปิดหน้าเว็บบน LINE App เพื่อให้พนักงานผูกบัญชีของตัวเอง

---

## 2. ขั้นตอนการตั้งค่าใน LINE Developers Console

### 2.1 สร้าง Provider และ Channel
1. เข้าไปที่ [LINE Developers Console](https://developers.line.biz/) และล็อกอินด้วยบัญชี LINE Business
2. คลิก **Create a new Provider** (หากยังไม่มี) และตั้งชื่อผู้ให้บริการ (เช่น ชื่อบริษัทของคุณ)
3. ภายใต้ Provider ที่สร้าง ให้สร้าง Channel สองประเภทดังนี้:
   * **Messaging API Channel** (สำหรับ LINE OA บอทตอบโต้อัตโนมัติและการส่งแจ้งเตือน)
   * **LINE Login Channel** (สำหรับทำ LIFF App เพื่อให้พนักงานผูกบัญชี)

---

### 2.2 การตั้งค่า Messaging API (LINE OA Settings)
1. ไปที่ Channel **Messaging API** ที่สร้างไว้
2. เลื่อนลงมาที่หัวข้อ **Channel settings** และคัดลอก **Channel secret** ไว้ (นี่คือ `LINE_CHANNEL_SECRET`)
3. ไปที่แท็บ **Messaging API settings**:
   * เลื่อนลงมาด้านล่างสุดในหัวข้อ **Channel access token** คลิก **Issue** เพื่อสร้าง Token และคัดลอกค่าไว้ (นี่คือ `LINE_CHANNEL_ACCESS_TOKEN`)
   * ในหัวข้อ **Webhook settings**:
     * ใส่ **Webhook URL**: ระบุลิงก์ Backend Webhook ของคุณ ตัวอย่างเช่น:
       `https://<your-public-frontend-url>/api/v1/line/webhook`
     * กด **Verify** เพื่อทดสอบการเชื่อมต่อ (ระบบต้องตอบกลับสถานะ HTTP 200 OK)
     * เปิดใช้งาน **Use webhook** (Toggle switch)
   * ในหัวข้อ **Using LINE Official Account features**:
     * ปิด **Auto-response messages** ใน LINE Official Account Manager (เพื่อไม่ให้บอทพื้นฐานของ LINE ตอบข้อความซ้ำซ้อนกับระบบเรา)
     * ปิด **Greeting messages** (หากต้องการใช้ระบบต้อนรับและส่ง Flex Message ของเราเอง)

---

### 2.3 การตั้งค่า LINE Login & LIFF Application
1. ไปที่ Channel **LINE Login** ที่สร้างไว้
2. ไปที่แท็บ **LIFF** แล้วคลิก **Add LIFF**
3. กรอกข้อมูลรายละเอียดของ LIFF App:
   * **LIFF app name**: ตั้งชื่อแอป (เช่น "WorkDee Register")
   * **Size**: เลือก **Full** เพื่อให้หน้าจอแสดงผลได้เต็มขนาด
   * **Endpoint URL**: ระบุ **prefix ที่คลุมหน้า LIFF ทุกหน้า** — ค่าที่ใช้จริงคือปลายทางระดับ `/liff` ตัวอย่างเช่น:
     `https://<your-public-frontend-url>/liff` (หน้าจริงคือ `/liff`, `/liff/checkin`, `/liff/register` — ดูข้อ 2.5)
     *อย่าตั้งเป็น root ของเว็บ* เพราะ `https://liff.line.me/<LIFF_ID>` จะเด้งไป dashboard → `/login`
   * **Scopes**: ติ๊กเลือก `profile` และ `openid`
   * **Features**: เปิดใช้งาน **ScanQR** (หากต้องการให้พนักงานสแกน QR code ผ่าน LIFF ได้)
4. กด **Save**
5. ระบบจะแสดง **LIFF ID** (เช่น `2000000000-XXXXXXXX`) ให้คัดลอกเก็บไว้ (นี่คือ `LINE_LIFF_ID`)
6. ไปที่แท็บ **LINE Login settings**:
   * ในส่วน **Callback URL** ให้ใส่ URL ของระบบเช่นกัน (ปกติ LIFF จะจัดการ Redirect ให้อัตโนมัติ แต่การใส่ Callback URL สำรองไว้จะช่วยป้องกัน Error ได้)
7. **ผูก LINE Official Account เข้ากับ LINE Login channel (จำเป็น — ถ้าไม่ทำ ขั้นตอนตรวจสอบการเป็นเพื่อนจะใช้ไม่ได้)**
   * ไปที่ LINE Developers Console → Provider **WorkDee** → Channel **LINE Login** → หัวข้อ **Linked LINE Official Account**
   * เลือก Official Account ของระบบ (`@416bveyk`) — **ต้องอยู่ Provider เดียวกัน** กับ LINE Login channel
   * กด **Save** *(ชื่อหัวข้อ/ปุ่มตามที่เห็นใน Console เมื่อ 2026-09-29)*
   * **อาการถ้าไม่ทำขั้นนี้:** `liff.getFriendship()` จะ throw `There is no login bot linked to this channel` → friendship gate ในหน้า LIFF จะถูกข้ามไปเงียบ ๆ (fail open) → พนักงานที่ยังไม่ได้เพิ่มเพื่อน OA ก็ลงทะเบียนได้ → ตอนอนุมัติจะได้ `push_status = skipped_not_friend` คือส่งข้อความต้อนรับไม่ได้ และบนมือถือจะไม่มี chat ของ OA โผล่มาเลย

> เมื่อนำโปรเจกต์นี้ไปเริ่มโปรเจกต์ใหม่ที่ใช้ OA คนละตัว ให้ **วางไฟล์ QR เพิ่มเพื่อนของ OA ใหม่ทับชื่อเดิม**
> (`frontend/public/line/oa-add-friend-qr.png`) แล้วตั้งค่า `line_basic_id` ให้ตรงกับ OA นั้น
> ที่ **Settings → แท็บ LINE → ช่อง LINE Basic ID (OA)** (ต้องมีเครื่องหมาย `@` นำหน้า)

### 2.4 การยืนยันตัวตนของพนักงานด้วย LINE ID Token (ต้องเปิด scope `openid`)

หน้า LIFF ไม่ได้ส่ง "LINE User ID" ที่พิมพ์เองได้ไปให้ระบบอีกต่อไป แต่จะส่ง **LINE ID Token**
(`liff.getIDToken()`) มาใน header `Authorization: Bearer <id_token>` แล้วฝั่ง Backend ตรวจกับ LINE
(`POST https://api.line.me/oauth2/v2.1/verify`) ก่อนใช้งาน — ถ้าตรวจไม่ได้ จะไม่รับข้อมูลนั้นเลย

สิ่งที่ต้องตั้งค่าให้ครบ ไม่งั้นพนักงานจะลงทะเบียนไม่ได้:

1. **เปิด scope `openid`** (และ `profile`) ของ LIFF app — ดูข้อ 2.3 ข้อ 3 ถ้าไม่เปิด `liff.getIDToken()`
   จะคืนค่า `null` และหน้า `/liff/register` จะแจ้งว่า **"ไม่พบข้อมูลยืนยันตัวตนจาก LINE กรุณาเปิดหน้านี้จากแอป LINE ..."**
2. **LIFF app ต้องอยู่บน LINE Login channel เดียวกับที่ระบบใช้** — ระบบหา `client_id` จาก **ส่วนนำหน้า
   ของ LIFF ID** (ก่อนเครื่องหมาย `-`) เช่น LIFF ID `2000000000-XXXXXXXX` จะใช้ `client_id = 2000000000`
   ดังนั้นถ้า LIFF ID มาจาก LINE Login channel อื่น ระบบจะตอบ **401** (เพราะ `aud` ของ token ไม่ตรง)

ข้อความที่พนักงานจะเห็นเมื่อตรวจสอบไม่ผ่าน:
* Token หมดอายุ/ไม่ถูกต้อง → **"เซสชัน LINE หมดอายุ กรุณาปิดแล้วเปิดหน้านี้ใหม่จาก LINE"** (401)
* ติดต่อ LINE ไม่ได้ / ยังไม่ได้ตั้งค่า LIFF ID ให้ถูกรูปแบบ → **"ตรวจสอบตัวตนไม่ได้ในขณะนี้ กรุณาลองใหม่อีกครั้ง"** (503)

> [!NOTE]
> ID Token เป็น bearer token ที่มีอายุประมาณ 1 ชั่วโมง — ผู้ที่ได้ token ไปจะใช้ได้จนกว่าจะหมดอายุ
> (ยอมรับความเสี่ยงนี้ในงาน 018 ไม่ได้ทำระบบ nonce/replay เพิ่ม)

### 2.5 หน้า "ลงเวลา" (`/liff/checkin`) เปิดจาก LINE อย่างไร

ตอนนี้มีหน้า LIFF 6 หน้า โดย 5 หน้าแรกใช้ **LINE ID Token ตัวเดียวกัน** ในการยืนยันตัวตน
(หน้า `/liff/portal` ไม่ต้องใช้ เพราะไม่แสดงข้อมูลส่วนตัว)

| หน้า | หน้าที่ |
|---|---|
| `/liff` | **ประตูทางเข้า (Endpoint URL)** — เปิด SDK แล้วพาไปหน้าที่ลิงก์ขอมา ถ้าไม่มี path ให้แสดงข้อความไทย + ลิงก์ 2 ปุ่ม |
| `/liff/register` | ขอผูกบัญชี LINE กับรหัสพนักงาน (ส่งคำขอ → รอ Admin อนุมัติ) |
| `/liff/checkin` | พนักงานลงเวลาทำงาน (ดูรอบของวันนี้ → กด "ลงเวลา") |
| `/liff/history` | **ประวัติการลงเวลาของตัวเอง** (งาน 029) — เลือกดูรายเดือน ย้อนหลังได้ 12 เดือน (อ่านเท่านั้น ไม่มีการแก้ไขข้อมูล) |
| `/liff/rounds` | **รอบลงเวลาของฉัน** (งาน 030) — ดูรอบที่ได้รับ เวลาที่ลงเวลาได้ สถานที่ที่ลงได้ และว่าต้องถ่ายรูปไหม พร้อมปุ่ม "ไปหน้าลงเวลา" |
| `/liff/portal` | **ศูนย์รวมบริการ** (งาน 031) — รวมบริการทั้งหมดของพนักงาน (ที่ใช้ได้แล้ว 3 บริการ + ที่กำลังจะเปิด 6 บริการ) เป็นทางเข้าหลักที่ไม่ต้องใช้ LIFF SDK และเปิดในเบราว์เซอร์นอก LINE ได้ |

**Endpoint URL ที่ต้องตั้งใน LINE Developers Console:** `https://<public-url>/liff`
คือ **prefix ที่คลุมหน้า LIFF ทุกหน้า** (ไม่ใช่ `/liff/register` แบบเดิม และไม่ใช่ root ของเว็บ)

**LINE เปิด URL อะไรให้** (ยืนยันจาก SDK 2.31.0 และการเปิดจริงผ่าน public host):

| ลิงก์ที่พนักงานได้รับ | LINE เปิดหน้าที่ฝั่งเว็บ | ผลลัพธ์ |
|---|---|---|
| `https://liff.line.me/<LIFF_ID>` | `…/liff` | หน้า `/liff` แสดงข้อความ "เปิดหน้าลงเวลาหรือลงทะเบียนจากลิงก์ที่ได้รับ" + ลิงก์ 2 ปุ่ม |
| `https://liff.line.me/<LIFF_ID>/checkin` | `…/liff/checkin` (LINE ต่อ path ให้) หรือ `…/liff?liff.state=%2Fcheckin` | หน้าลงเวลา |
| `https://liff.line.me/<LIFF_ID>/register` | `…/liff/register` หรือ `…/liff?liff.state=%2Fregister` | หน้าลงทะเบียน |
| `https://liff.line.me/<LIFF_ID>/history` | `…/liff/history` หรือ `…/liff?liff.state=%2Fhistory` | หน้าประวัติการลงเวลา |
| `https://liff.line.me/<LIFF_ID>/rounds` | `…/liff/rounds` หรือ `…/liff?liff.state=%2Frounds` | หน้ารอบลงเวลาของฉัน (งาน 030) |
| `https://liff.line.me/<LIFF_ID>/portal` | `…/liff/portal` หรือ `…/liff?liff.state=%2Fportal` | หน้าศูนย์รวมบริการ (งาน 031) |

**หน้าที่ `/liff` ทำอะไร:** โหลด LIFF SDK → `fetch('/api/v1/settings')` เอา LIFF ID → `liff.init()`
→ **หลัง init เท่านั้น** ถ้ามี `liff.state` จะ `location.replace()` ไปหน้าปลายทาง (รวม path ของ Endpoint URL
ไว้ข้างหน้า และคงพารามิเตอร์ `liff.*` เดิมไว้) ถ้าไม่มี `liff.state` จะแสดงข้อความไทย + ลิงก์ 2 ปุ่ม
หน้านี้ **ไม่เรียก `liff.login()`** เพราะเป็นเพียงทางผ่าน (หน้าปลายทางจัดการเรื่องล็อกอินเอง)

> [!IMPORTANT]
> **ทำไมต้องมีหน้า `/liff`:** เวลาพนักงานเปิดใน **external browser** แล้วยังไม่ได้ล็อกอิน
> หน้าลงเวลาจะเรียก `liff.login()` ซึ่ง LINE จะกลับมาที่ `redirect_uri` = **Endpoint URL** (`…/liff`) เสมอ
> (หลักฐานจากการเปิดจริง: `redirect_uri=https://<public-https-host>/liff` โดย `<public-https-host>` คือโฮสต์ HTTPS สาธารณะที่ LINE เข้าถึง backend ได้ — ใส่โดเมนจริงหรือ tunnel ของคุณเอง)
> ถ้าไม่มีหน้านี้ พนักงานจะเจอ **404 หลังล็อกอิน** — ซึ่งเป็นอาการ "วงกลมหมุนแล้วขึ้น 404" ที่เจอบนมือถือ
> ดังนั้นหน้า `/liff` จึงเป็นส่วนที่จำเป็น ไม่ใช่แค่เรื่องความสวยงาม

> [!WARNING]
> **อย่าเปลี่ยน Endpoint URL ให้เป็น path อื่น** (เช่น `…/liff/checkin` หรือ root ของเว็บ): ถ้าเป็น root ของเว็บ
> `https://liff.line.me/<LIFF_ID>` จะเด้งไปหน้า dashboard → `/login` (หน้าล็อกอินของแอดมิน) ซึ่งเป็นอาการที่เคยเจอ
> และถ้าเป็น path ที่ไม่มีหน้า จะได้ 404 ทันที

**สิ่งที่ต้องมีเหมือนหน้า register:** scope `profile` และ `openid` (ไม่งั้น `liff.getIDToken()` คืน `null`
แล้วหน้าลงเวลาจะแจ้ง **"ไม่พบข้อมูลยืนยันตัวตนจาก LINE กรุณาเปิดหน้านี้จากแอป LINE อีกครั้ง ..."**) และต้อง
**เปิดจากในแอป LINE** เพราะหน้าเว็บไม่ให้พนักงานพิมพ์รหัสพนักงานหรือ LINE User ID เองเลย

## 3. การกรอกข้อมูลบนระบบ WorkDee

ผู้ดูแลระบบสามารถกำหนดค่าได้ 2 วิธีการ:

### วิธีที่ 1: ตั้งค่าผ่าน Admin Dashboard UI (แนะนำ)
1. ล็อกอินเข้าสู่ระบบ WorkDee ด้วยสิทธิ์ผู้ดูแลระบบ (Admin/Staff)
2. ไปที่เมนู **System Settings** (หน้าปรับแต่งระบบ)
3. เลื่อนลงมาที่เซกชัน **LINE OA & LIFF Integration Settings**
4. กรอกข้อมูลที่คัดลอกมา:
   * **LINE Channel Access Token**
   * **LINE Channel Secret**
   * **LINE LIFF ID**
   * **LINE Basic ID (OA)** — Basic ID ของ OA พร้อมเครื่องหมาย `@` นำหน้า (ตัวอย่าง `@416bveyk`) ใช้สร้างลิงก์/ปุ่มเพิ่มเพื่อน OA ในแท็บ **Add Friend** ของหน้า LINE OA Binding และในหน้าให้เพิ่มเพื่อนของ LIFF
5. คลิก **Save Changes** เพื่อบันทึกค่าลงในฐานข้อมูลโดยตรง ค่านี้จะมีผลใช้งานทันทีโดยไม่ต้อง Restart Server

> [!NOTE]
> เพื่อความปลอดภัย ข้อมูล Access Token และ Channel Secret จะถูกซ่อนและสลับเปิด-ปิดตาได้เฉพาะ Admin เท่านั้น และจะไม่แสดงผลผ่าน API สาธารณะ

### วิธีที่ 2: ตั้งค่าผ่าน Env Variable (สำหรับ Fallback หรือเครื่องจำลอง)
หากยังไม่ได้ตั้งค่าในฐานข้อมูล คุณสามารถกำหนดค่าลงในไฟล์ `.env` ของฝั่ง Backend (`backend/.env`) ได้ในลักษณะตัวสำรอง (Fallback) โดยระบบจะเลือกใช้ค่าจาก Database ก่อนเป็นหลัก และจะไม่มีความจำเป็นต้องกำหนดค่าในฝั่ง Frontend (`frontend/.env.local`) อีกต่อไปเนื่องจากระบบจะดาวน์โหลดการตั้งค่าจากหลังบ้านแบบไดนามิกโดยตรง:
```env
LINE_CHANNEL_ACCESS_TOKEN=your_token_here
LINE_CHANNEL_SECRET=your_secret_here
LINE_LIFF_ID=your_liff_id_here
```

## 4. ข้อแนะนำสำหรับการพัฒนาบนเครื่องจำลอง (Local Development & Tunnel)

การทดสอบ LIFF/Webhook บนเครื่องตัวเองต้องมี URL แบบ HTTPS ที่เข้าถึงได้จากอินเทอร์เน็ต (เช่น tunnel) เพราะเซิร์ฟเวอร์ของ LINE ต้องเป็นฝ่ายดึงหน้า LIFF และยิง Webhook เข้ามาเอง — ใช้บริการ tunnel ใดก็ได้ตามถนัด คู่มือนี้ไม่ผูกกับเจ้าไหน

### ข้อควรระวังที่พบบ่อย
1. **หน้าคั่นยืนยันของผู้ให้บริการ tunnel (interstitial)** — ถ้า tunnel เปิดหน้าให้กดยอมรับก่อนเข้าถึง ต้องเปิด URL นั้นในเบราว์เซอร์ของมือถือก่อนหนึ่งครั้งแล้วกดยอมรับ เพราะหน้า LIFF ที่ LINE เปิดจะข้ามหน้านี้ให้เองไม่ได้ (ผู้ใช้จะเจอหน้านั้นแทนหน้าเว็บของเรา)
2. **เปลี่ยน URL ของ tunnel แล้วต้องอัปเดตทุกที่ที่อ้างอิงถึง** ได้แก่ LIFF **Endpoint URL**, Messaging API **Webhook URL** และค่า `NEXT_PUBLIC_LIFF_API_URL` ใน `frontend/.env.local` (ค่านี้กำหนด origin ที่ `next dev` ยอมให้โหลดไฟล์ของตัวเอง — ถ้าไม่ตรง หน้าจะโหลดแต่จะว่างเปล่า)
3. **ต้องเป็น HTTPS** และต้องเปิด **Use webhook** ให้ครบ (ดูข้อ 2.2)

## 5. การทดสอบความถูกต้องของระบบ (Verification checklist)

เมื่อตั้งค่าเสร็จแล้ว สามารถตรวจสอบการทำงานได้ดังนี้:
1. **Webhook verification**: ส่งข้อความสุ่มเข้าไลน์บอท -> บอทจะต้องตอบกลับ Flex Message แสดงปุ่ม "👉 เริ่มต้นลงทะเบียน 👈"
2. **LIFF Binding Flow**: คลิกปุ่มลงทะเบียนใน LINE -> หน้า LIFF จะเปิดหน้าสมัครสมาชิก -> เมื่อพนักงานกรอกรหัสพนักงานและกดลงทะเบียน -> สถานะการผูกบัญชีจะขึ้นเป็น `PENDING` ในแผงควบคุม
3. **Approval Notification**: เมื่อ Admin กดอนุมัติการผูกบัญชีในหน้ารายการ -> พนักงานจะได้รับ Push Notification ต้อนรับเข้าสู่ระบบโดยอัตโนมัติ
4. **เมนูพนักงาน (Rich Menu)**: หน้า **LINE OA Binding** จะมีการ์ด **"เมนูพนักงาน"** — กดปุ่ม *สร้าง/อัปเดตเมนูและเชื่อมกับพนักงาน* แล้วพนักงานที่ผูกบัญชีสถานะ `APPROVED` จะเห็นเมนูด้านล่างหน้าจอแชทของ OA (ปุ่ม **ลงเวลา** ใช้งานได้จริง ที่เหลือตอบกลับว่า "ฟังก์ชันนี้กำลังจะเปิดให้ใช้เร็วๆ นี้ค่ะ/ครับ")

## 6. เมนูพนักงาน (Rich Menu)

เมนูพนักงานคือแถบปุ่ม 4 ช่องที่แสดงอยู่ **ด้านล่างหน้าจอแชท** ของ OA ใช้รูปเดียวขนาด **2500 × 1686 พิกเซล**
(ตาราง 2 × 2 ช่องละ 1250 × 843) ประกอบด้วย

| ปุ่ม | การทำงาน |
|---|---|
| **ลงเวลา** | เปิดหน้า LIFF `/checkin` (`https://liff.line.me/<LIFF_ID>/checkin`) — ใช้ได้จริงแล้ว |
| **รอบของฉัน** | เปิดหน้า LIFF `/rounds` (`https://liff.line.me/<LIFF_ID>/rounds`) — **ใช้ได้จริงแล้ว** (งาน 030) ดูรอบที่ได้รับ เวลาที่ลงได้ สถานที่ และปุ่ม "ไปหน้าลงเวลา" |
| **ประวัติการลงเวลา** | เปิดหน้า LIFF `/history` (`https://liff.line.me/<LIFF_ID>/history`) — **ใช้ได้จริงแล้ว** (งาน 029) ดูประวัติการลงเวลาของตัวเองย้อนหลัง 12 เดือน |
| **ศูนย์รวมบริการ** | เปิดหน้า LIFF `/portal` (`https://liff.line.me/<LIFF_ID>/portal`) — **ใช้ได้จริงแล้ว** (งาน 031) รวมบริการทั้งหมดของพนักงาน |

**ทั้ง 4 ปุ่มเป็นลิงก์ทั้งหมดแล้ว (งาน 031) — ไม่มีปุ่ม "เร็วๆ นี้" ในเมนูอีกต่อไป** ระบบจึงไม่ส่ง
`postback` ใด ๆ จากเมนูเลย และรูปเมนูไม่มีป้าย "เร็วๆ นี้" แล้ว

> **หลังอัปเดตงาน 031 ต้องกดปุ่ม "สร้าง/อัปเดตเมนูและเชื่อมกับพนักงาน" หนึ่งครั้ง** เพื่อให้เมนูใหม่
> (ปุ่ม **ศูนย์รวมบริการ** กลายเป็นลิงก์ เป็นปุ่มสุดท้ายที่เปิดใช้) มีผลกับเครื่องของพนักงาน
> การกดซ้ำปลอดภัย — ระบบลบเมนูเดิมให้เอง
> เครื่องที่ยังถือเมนูเก่าอยู่จะยังกดปุ่มเดิมได้ และจะได้ข้อความ "เร็วๆ นี้" เหมือนเดิมจนกว่าจะอัปเดต
> (ระบบยังตอบข้อความนั้นให้ค่าเก่าทั้งสาม: `soon:portal`, `soon:my-rounds`, `soon:history`)

### 6.1 ใครเห็นเมนูนี้
ระบบเชื่อมเมนูแบบ **รายคน (per-user)** ให้เฉพาะพนักงานที่มีสถานะการผูกบัญชีเป็น `APPROVED` เท่านั้น
**ไม่มีการตั้งเป็นเมนูเริ่มต้น (default)** ของ OA เพราะถ้าตั้งเป็น default ทุกคนที่เพิ่มเพื่อน OA จะเห็นเมนู
รวมถึงคนที่ยังไม่ได้ผูกบัญชี/ไม่อยู่ในระบบ

- กดอนุมัติการผูกบัญชี → ระบบเชื่อมเมนูให้พนักงานคนนั้นทันที
- กดเพิกถอนการผูกบัญชี → ระบบถอดเมนูออกจากคนนั้นทันที
- ถ้าการเชื่อมเมนูกับ LINE ล้มเหลว **การอนุมัติ/เพิกถอนจะยังสำเร็จตามปกติ** (สถานะการผูกบัญชีไม่ถูกย้อนกลับ)
  โดยระบบจะรายงานผลในฟิลด์ `menu_status` ของคำตอบ API (`linked` / `unlinked` / `skipped_no_menu` /
  `skipped_no_token` / `failed`) และเขียน log ระดับ WARNING ไว้ 1 บรรทัด — ซ่อมได้ด้วยการกดปุ่มสร้าง/อัปเดตเมนูอีกครั้ง

### 6.2 วิธีสร้าง/อัปเดตเมนู
1. ล็อกอินด้วยบัญชีที่มีสิทธิ์เมนู **LINE OA Binding**
2. การ์ด **"เมนูพนักงาน"** จะแสดงสถานะ (มีเมนูแล้ว / ยังไม่ได้สร้าง) และจำนวนพนักงานที่ผูกบัญชีแล้ว
3. กดปุ่ม **"สร้าง/อัปเดตเมนูและเชื่อมกับพนักงาน"** → ยืนยันในกล่องยืนยัน (กล่องนี้จะบอกจำนวนพนักงานที่จะได้รับเมนู)
4. ระบบจะทำงานตามลำดับ: ตรวจเมนูเดิม → สร้างเมนูใหม่ → อัปโหลดรูป → เชื่อมให้พนักงานเป็นชุด (ครั้งละไม่เกิน 500 คน) → ลบเมนูเดิม
5. ผลลัพธ์จะแสดงจำนวน **เชื่อมสำเร็จ / ไม่สำเร็จ / ข้าม** — กดปุ่มซ้ำได้เสมอ (ไม่ทำให้เกิดเมนูซ้ำ เพราะระบบลบเมนูชื่อเดียวกันที่ไม่ใช่ตัวใหม่ทิ้ง)

> [!NOTE]
> การ์ดนี้ **ไม่เรียก LINE ตอนเปิดหน้า** เพื่อไม่ให้มีการยิงไปยัง OA จริงโดยไม่ตั้งใจ สถานะ "มีเมนูแล้ว/ยังไม่ได้สร้าง"
> จึงหมายถึง "เมนูที่สร้างโดยเซิร์ฟเวอร์รอบล่าสุด" — ถ้าเพิ่งรีสตาร์ทเซิร์ฟเวอร์ การ์ดจะแสดง *ยังไม่ได้สร้าง* จนกว่าจะกดปุ่ม
> (การกดปุ่มซ้ำปลอดภัย เพราะเป็นการสร้างใหม่และลบของเดิม) ส่วนจำนวนพนักงานที่ผูกบัญชีแล้วนับจากฐานข้อมูลจริงเสมอ
>
> ถ้ายังไม่ได้ตั้งค่า **Channel Access Token** หรือ **LIFF ID** ปุ่มจะถูกปิดและขึ้นข้อความเตือน (ดูข้อ 3)

### 6.3 เปลี่ยนรูปเมนู
รูปที่อัปโหลดขึ้น LINE ถูกเก็บในโปรเจกต์พร้อมไฟล์ต้นฉบับ:
```
backend/app/assets/rich_menu/workdee-employee-menu.png   <- รูปที่อัปโหลด (PNG 2500 × 1686 ไม่เกิน 1 MB)
backend/app/assets/rich_menu/workdee-employee-menu.html  <- ต้นฉบับ ใช้สร้างรูปใหม่
```
รูปปัจจุบัน (งาน 031) ทั้ง 4 ช่องเป็นปุ่มที่ใช้งานได้: ช่อง **ลงเวลา** เป็นสี่นํ้าเงินหนดิเจน (เด็ดที่สุด)
ส่วนอีกสามช่องเป็นกรอบสีนํ้าเงินพร้อมข้อความจาง (รอบของฉัน / ประวัติการลงเวลา / ศูนย์รวมบริการ)
และ **ไม่มีป้าย "เร็วๆ นี้" ในรูปอีกแล้ว**
วิธีแก้รูป: แก้ไฟล์ `.html` (ข้อความ/สี/ไอคอน) → เรนเดอร์ใหม่ด้วย Chrome แบบ headless → กดปุ่มสร้าง/อัปเดตเมนูอีกครั้ง
```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu --hide-scrollbars `
  --force-device-scale-factor=1 --window-size=2500,1686 `
  --user-data-dir=".scratch\chrome-menu" `
  --screenshot="backend\app\assets\rich_menu\workdee-employee-menu.png" `
  "file:///<พาธเต็มของโปรเจกต์>/backend/app/assets/rich_menu/workdee-employee-menu.html"
```
> [!CAUTION]
> ต้องมี `--user-data-dir` เสมอ: ถ้ามี Chrome ของผู้ใช้เปิดอยู่ การเรียกโดยไม่มีค่านี้จะถูกส่งต่อให้ Chrome
> ตัวที่เปิดอยู่ **แล้วจบไปโดยไม่เขียนไฟล์** (เจอจริงตอนเรนเดอร์งาน 030 — รูปเดิมค้างอยู่และดูเหมือนสำเร็จ)
> ถ้าต้องสงสัย ให้เทียบเวลาแก้ไขไฟล์และแฮช SHA-256 หลังเรนเดอร์ทุกครั้ง
> [!IMPORTANT]
> พิกัดปุ่ม (bounds) ในเมนูต้องตรงกับรูปเสมอ — ค่าที่ส่งให้ LINE คำนวณจาก `area_bounds()`
> ใน `backend/app/line_richmenu.py` (ช่องละ 1250 × 843) ซึ่งตรงกับตำแหน่งช่องทั้ง 4 ในไฟล์ HTML
> ถ้าแก้ตำแหน่งรูป ต้องแก้ทั้งสองที่
> และ LINE **แทนที่รูปของเมนูเดิมไม่ได้** ต้องสร้างเมนูใหม่ (ซึ่งปุ่มในหน้านี้ทำอยู่แล้ว)

### 6.4 LIFF Endpoint URL ต้องคงไว้ที่ `/liff`
ปุ่มทั้ง 4 เปิด `https://liff.line.me/<LIFF_ID>/checkin`, `/rounds`, `/history` และ `/portal`
โดยอาศัย LIFF app ที่มี Endpoint URL เป็น `…/liff` (หน้า `/liff` ทำหน้าที่เป็นทางผ่านแล้วส่งต่อไปหน้าปลายทางเอง)
**อย่าเปลี่ยน Endpoint URL** ให้เป็น path อื่น ไม่งั้นปุ่มในเมนูจะพาไปหน้า 404 หรือไปหน้า `/login` ของแอดมิน

### 6.5 เพิ่มบริการใหม่เข้าศูนย์รวมบริการ (งาน 031)
หน้า **ศูนย์รวมบริการ** (`/liff/portal`) อ่านรายการบริการจากที่เดียวคือ
`frontend/src/app/liff/portal/services.ts` — ยังไม่มีหน้าแอดมินสำหรับแก้รายการนี้ (ตั้งใจให้เป็นงานของทีมพัฒนา)

1. **เปิดบริการใหม่:** สร้างหน้า LIFF ของบริการนั้น (เช่น `/liff/news`) แล้วแก้รายการที่มีอยู่จาก
   `status: "soon"` เป็น `status: "live"` พร้อมใส่ `href: "/liff/news"` → เหลือแค่ deployment ตามปกติ
   **ไม่ต้องกดปุ่มสร้างเมนูใหม่ และไม่ต้องเปลี่ยนรูปเมนู** เพราะเมนูมี 4 ปุ่มตายตัว (นี่คือเหตุผลที่มีหน้านี้)
2. **เพิ่มบริการใหม่ (ที่ยังไม่เปิด):** เพิ่มรายการใหม่ `status: "soon"` หนึ่งบรรทัด (ไม่ต้องมี `href`)
   → ขึ้นเป็นการ์ดสีจาง ๆ ในหัวข้อ "เร็วๆ นี้"
3. **กติกาที่ระบบตรวจให้:** `key` ห้ามซ้ำ, รายการที่ `live` ต้องมี `href` ขึ้นต้นด้วย `/liff/` เท่านั้น,
   รายการที่ `soon` ห้ามมี `href` (ตรวจใน `verify031` และเรียกได้จาก `portalServiceProblems()`)
4. **ข้อจำกัดที่รู้อยู่:** ทุกคนที่ผูกบัญชีแล้วเห็นศูนย์รวมบริการเหมือนกันทั้งหมด ยังไม่มีการกำหนดสิทธิ์รายบุคคล
   ส่วนหน้าที่ใช้ข้อมูลส่วนตัว (`/checkin`, `/rounds`, `/history`) ตรวจสิทธิ์ของตัวเองอยู่แล้ว
