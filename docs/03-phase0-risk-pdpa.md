### 3.4 กลไกบริหารความเสี่ยง (Risk Mitigations)

#### 3.4.1 การตรวจสอบความแม่นยำของพิกัด (GPS Accuracy Check)

- ระบบอ่านค่าพิกัดพร้อมค่า `accuracy` จาก Geolocation API
- ถ้า `accuracy > 100 เมตร` → แสดงข้อความแนะนำให้เปิด Wi-Fi ช่วยจับตำแหน่ง
- ถ้า `accuracy > 200 เมตร` → ไม่ auto-approve แม้อยู่ในช่วง 100–200 ม.

#### 3.4.2 การป้องปราม Mock Location (Mock Location Detection)

- ตรวจสอบ `isFromMockProvider` flag บน Android
- บน iOS ตรวจสอบ `CLLocationSourceInformation`
- **ถ้าตรวจเจอ:**
  - บันทึก Log แต่ **ติด Flag แดงเข้ม**
  - **ไม่ auto-approve** ทุกกรณี
  - แจ้ง HR ทันทีผ่าน Flagged Review Center

#### 3.4.3 การถ่ายภาพเชิงจิตวิทยา (Psychological Photo Capture)

**แนวคิด:** ใช้ "ความเกรงใจ" และ "การมีหลักฐาน" เป็นกลไกทางสังคม ป้องกันการฝากตอกบัตร โดยไม่ต้องใช้ AI เปรียบเทียบภาพ

**กลไก:**
1. หน้าจอลงเวลาจะแสดง **"ภาพตัวอย่างอ้างอิง (Reference Thumbnail)"** ของบรรยากาศที่ทำงาน
2. เปิด **กล้องสด** จากหน้าเว็บโดยตรง (ไม่เปิดช่องให้เลือกไฟล์จาก Gallery)
3. ถ่ายภาพบรรยากาศ ณ ตอนนั้น
4. **ไม่ใช้ AI เปรียบเทียบ** — ใช้เป็นหลักฐานแนบใน Log เท่านั้น
5. **ถ้าถ่ายภาพไม่ได้ ระบบยังลงเวลาให้** และบันทึกเป็น `PHOTO_MISSING` ให้ฝ่ายบุคคลตรวจ
   (งาน 026: การลงเวลาไม่ถูกบล็อกจากกรณีภาพถ่าย — กติกาที่ใช้จริงอยู่ใน `docs/02-phase0-entities.md`)

**นโยบายการจัดเก็บภาพ (Photo Retention Policy):**
- เก็บภาพไว้ **90 วัน** แล้วลบอัตโนมัติ
- เฉพาะ HR ที่มีสิทธิ์เท่านั้นที่เข้าถึงภาพได้
- พนักงานสามารถขอดูภาพของตนเองได้
- ภาพถูกเข้ารหัส (Encrypted at Rest)

#### 3.4.4 กฎการอนุมัติอัตโนมัติ (Auto-Approve Rules)

| ระยะห่าง | เงื่อนไข | การจัดการ |
|---|---|---|
| อยู่ในรัศมี | - | ผ่านทันที |
| 100–200 ม. | มีเหตุผล + GPS Accuracy ≤ 100 ม. + ไม่มี Mock Flag | Auto-Approve (Flag เหลือง) |
| 100–200 ม. | GPS Accuracy > 100 ม. หรือมี Mock Flag | Flag แดง → HR ตรวจ |
| > 200 ม. | - | Flag แดง → HR ตรวจ |

**หมายเหตุ:** ถ้าพนักงานคนเดิมติด Flag แดงซ้ำหลายครั้ง ระบบจะ **ไม่ auto-approve** แม้ระยะห่างจะอยู่ในช่วง 100–200 ม.

### 3.5 การปฏิบัติตาม PDPA และ Consent Flow

#### 3.5.1 หลักการ

เนื่องจากการเก็บ **พิกัดบ้าน (WFH)** และ **ภาพถ่าย** เป็นข้อมูลส่วนบุคคลที่อ่อนไหวตาม PDPA มาตรา 26 ระบบจึงต้องมี **Consent Flow แบบ lightweight** ภายในแอป LIFF

#### 3.5.2 Consent Flow ในแอป

**ขั้นตอน:**
1. **ครั้งแรกที่เข้าใช้งาน LIFF** → แสดงหน้า Consent
2. ผู้ใช้ต้อง **ติ๊กถูก** และกด **"ยอมรับ"**
3. ระบบเก็บ:
   - `consent_timestamp`
   - `consent_version` (เวอร์ชันนโยบาย)
   - `consent_ip`
   - `line_user_id`
4. ผู้ใช้สามารถ **ถอนความยินยอม** ได้ตลอดผ่านหน้า Settings
5. ถ้าถอน → ฟีเจอร์ WFH และการถ่ายภาพจะถูกปิด แต่ยังลงเวลาแบบปกติได้ (ถ้าไม่ต้องใช้ภาพ)

#### 3.5.3 สิ่งที่ต้องขอความยินยอมแยก

| ประเภทข้อมูล | วัตถุประสงค์ | ผลหากไม่ยินยอม |
|---|---|---|
| พิกัดบ้าน (WFH) | ใช้ยืนยันการลงเวลาที่บ้าน | ใช้โหมด WFH ไม่ได้ |
| ภาพถ่าย | ใช้เป็นหลักฐานการลงเวลา | ลงเวลาต่อได้ แต่ระบบติด `PHOTO_MISSING` ให้ HR ตรวจ |
| พิกัดสำนักงาน | ใช้ยืนยันการอยู่ในพื้นที่ | ลงเวลาไม่ได้ |

#### 3.5.4 นโยบายการเก็บรักษาข้อมูล

| ประเภทข้อมูล | ระยะเวลาเก็บ | เหตุผล |
|---|---|---|
| Attendance Logs | 5 ปี | ตามกฎหมายแรงงาน |
| ภาพถ่าย | 90 วัน | ลดความเสี่ยง PDPA |
| พิกัดบ้าน | ตลอดที่ยังใช้ WFH | ลบเมื่อลาออก/ถอน consent |
| Consent Records | 5 ปีหลังถอน | เป็นหลักฐานทางกฎหมาย |
